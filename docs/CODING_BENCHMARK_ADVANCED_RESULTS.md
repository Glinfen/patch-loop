# DeepSeek V4 Flash 进阶代码任务评测

## 运行条件

- 日期：2026-08-30
- Provider：`deepseek-v4-flash`
- 套件：`patchloop-coding-advanced-v1`
- 任务数：4
- 外部验证：每项 1 个锁定隐藏测试文件，Agent 结束后才注入工作区
- 沙箱：`local`，只运行项目内受信任 fixture
- 采样：各配置 1 轮；复杂任务另做单项诊断，结果不合并为完整套件成绩

## 任务设计

| 任务 | 主要能力 | 隐藏验收重点 |
| --- | --- | --- |
| versioned-document-migration | 版本化迁移与深拷贝 | v2、当前版本、无共享引用、非法版本 |
| deterministic-feature-rollout | 精确算法规格与 Unicode | 百分比边界、分数阈值、确定性哈希 |
| atomic-bank-transfer | 跨文件功能与事务语义 | 输入校验、失败回滚、不可变回执 |
| escaped-query-parser-with-regression-test | 状态解析器与测试生成 | 全部转义、畸形输入、重复键、指定新增测试文件 |

所有 fixture 的公开测试在发布状态均失败。Fixture 和隐藏测试分别由仓库树 SHA-256 与文件 SHA-256 锁定；隐藏测试仅在 Agent 停止后注入，且不计入 Agent 的变更文件。

## 完整套件对照

基线已经 4/4 通过，因此本轮优化目标是减少无效动作，同时保持独立正确率。第一轮优化明确了 `run_tests` 只接受 pytest/unittest、计划应保持 2～4 个短项、通过测试后停止推测性重复验证，并要求最终答复不粘贴完整源码。

| 指标 | 基线 | 约束优化 | 变化 |
| --- | ---: | ---: | ---: |
| 独立成功率 | 4/4，100% | 4/4，100% | 不变 |
| Agent 完成率 | 4/4，100% | 4/4，100% | 不变 |
| 总步骤 | 40 | 38 | -5.00% |
| 工具调用 | 56 | 49 | -12.50% |
| 输入 Token | 290,653 | 314,267 | +8.12% |
| 输出 Token | 24,245 | 22,222 | -8.34% |
| 平均时延 | 54.52 秒 | 52.48 秒 | -3.74% |
| 估算费用 | 0.010583 美元 | 0.009793 美元 | -7.47% |

输入 Token 没有随工具数同步下降，原因集中在查询解析任务的一次较长采样。前三个任务合计输入 Token 从 158,499 降到 123,963，下降 21.79%；查询解析任务则从 132,154 增加到 190,304。因此不能根据单次完整套件断言输入成本已经稳定改善。

## 轨迹驱动优化

### 消除策略已知会拒绝的测试命令

基线中，版本迁移和灰度任务在 pytest 已通过后仍共尝试 3 次 `python -c`，均被执行策略拒绝。优化后此类尝试降为 0。`RunTestsTool` 的描述和 Runtime 契约现在直接声明只允许 pytest/unittest，并要求相关测试通过后停止重复或临时脚本检查。

### 控制重复发现与测试扩张

复杂解析任务的初始轨迹同时执行 `list_files`、`search_text` 和逐文件读取，并在只要求两个指定回归场景时新增了 13～15 个测试。最终提示要求小仓库列出文件后直接读取目标，并创建满足要求的最小聚焦测试。单项诊断保持隐藏测试通过，步骤从基线 13 降到 10，工具调用从 17 降到 12，失败工具调用从 2 降到 0；新增回归测试数量从 13 降到 8。

该单项采样的 Token 和时延仍高于基线，说明模型输出长度存在较大方差，不能只用步骤数代表总成本。

### 否决激进历史压缩

曾实验 8,000 Token 的历史软上限。它触发了 9 次结构化记忆压缩并继续通过隐藏测试，但查询解析任务上升到 21 步、23 次工具调用和 240,824 输入 Token。由于没有正向实测证据，该运行时代码已撤销；报告保留用于防止以后重复采用未经验证的优化方向。

## 证据与限制

机器可读报告：

- `benchmarks/results/code_benchmark_advanced_baseline.json`
- `benchmarks/results/code_benchmark_advanced_optimized.json`
- `benchmarks/results/code_benchmark_advanced_compacted.json`，已否决实验
- `benchmarks/results/code_benchmark_advanced_focused.json`，复杂任务单项诊断

四个任务仍是小型 Python fixture，每项每配置只有一次模型采样。结果证明 PatchLoop 在这些锁定任务上能完成跨文件修改、状态解析和测试生成，并能抵御公开测试不足；它不代表大型未知仓库上的通用成功率。后续应对最终配置重复 3～5 轮，并加入跨目录重构、依赖升级、并发缺陷和真实仓库留出集。
