# PatchLoop 长上下文与分层记忆开发计划

## 1. 目标

下一阶段目标是让 PatchLoop 在 50～120 个执行步骤、跨检查点恢复和强干扰上下文中，仍能正确保留约束、调用早期证据、识别已失败方案，并在固定 Token 预算内完成代码任务。

本阶段不会简单扩大模型上下文，也不会把所有历史交给模型。核心能力是建立可持久化、可检索、可追溯、可压缩的分层记忆系统：

- 短期工作记忆：保存当前阶段必须立即使用的状态。
- 长期语义记忆：保存事实、约束、接口、决策和测试结论。
- 长期情景记忆：保存一次行动过程的意图、动作、观察、结果和失败恢复。
- 分层压缩：把重复历史归并为更高层记忆，同时保留来源和恢复路径。

## 2. 当前能力与主要差距

当前 `ContextEngine` 已经具备有界消息选择、工具输出截断和 `TaskMemory` 抽取，能够在历史超出硬预算时保留部分早期证据。但它仍有以下边界：

| 当前机制 | 主要边界 |
| --- | --- |
| 从被丢弃消息临时构建 `TaskMemory` | 每次构建重新抽取，没有稳定的长期记忆实体 |
| 词项交集相关性 | 无法可靠处理同义表达、跨文件关系和多段证据组合 |
| `decisions`、`failures`、`key_evidence` 平铺保存 | 没有语义类型、置信度、重要度和生命周期 |
| 直接删除低优先级摘要字段以适配预算 | 缺少多代压缩、去重和关键事实保护机制 |
| 检查点保存消息与工具历史 | 恢复后不能按查询召回跨阶段记忆，也不能防止重复写入 |
| 只记录上下文选取结果 | 无法解释某条记忆为何写入、被替代、被召回或被压缩 |

上一轮 8,000 Token 历史软上限实验已经证明：提前裁剪本身不等于优化。该实验虽然保持正确性，但复杂任务从 13 步上升到 21 步。因此本阶段必须以记忆质量和端到端任务结果作为主判据，而不是只看上下文变短。

## 3. 记忆模型

### 3.1 短期工作记忆

短期工作记忆只覆盖当前任务阶段，保持小而精确，建议预算为模型上下文的 15%～25%。内容包括：

- 当前目标和活动计划项。
- 用户明确约束和禁止事项。
- 当前正在修改的文件、符号和未提交变更。
- 最近一次测试结果、当前错误和下一步假设。
- 尚未回答的问题和待验证条件。

工作记忆在每个步骤后增量更新，不追加完整历史。已解决问题、过期错误和离开当前阶段的细节应提升为长期记忆或删除。

### 3.2 长期语义记忆

语义记忆保存与时间顺序无强绑定、后续可能再次使用的知识：

- 任务约束：只能修改哪些文件、兼容性和安全要求。
- 仓库事实：模块职责、符号关系、数据格式和命令约定。
- 决策：选用的实现方案、拒绝的替代方案和理由。
- 验证事实：哪些测试通过、哪些边界尚未覆盖。
- 接口事实：函数签名、错误语义、配置优先级。

每条语义记忆必须具有来源、作用域、重要度、置信度和状态。状态至少包含 `active`、`superseded` 和 `invalidated`。新证据与旧事实冲突时不得静默覆盖，应建立替代关系，并默认召回最新且来源更可靠的有效事实。

### 3.3 长期情景记忆

情景记忆保存具有时间和因果关系的执行片段：

- 当时的意图和计划阶段。
- 执行的工具动作。
- 关键观察和变更文件。
- 成功、失败或被策略拒绝的结果。
- 从失败中得到的结论和后续恢复动作。

情景边界由计划阶段切换、写入、测试、失败恢复和检查点事件确定。典型查询是“上次为什么放弃这个实现”“哪个修改导致测试开始失败”“恢复前最后一个已验证状态是什么”。

### 3.4 统一记忆记录

建议新增 `MemoryRecord` 和 `MemorySource` 领域模型，至少包含：

- `id`、`task_id`、`kind`、`schema_version`。
- 结构化内容和面向检索的简短文本。
- 来源事件 ID、步骤号、工具调用 ID、文件与行号。
- `importance`、`confidence`、创建时间和最后访问时间。
- `status`、`supersedes_id`、内容哈希和压缩代数。
- 估算 Token、访问次数和最后召回原因。

原始 Trace 和工具结果继续作为不可变证据源。长期记忆是可重建的派生视图，不得成为唯一审计记录。

## 4. 建议模块结构

```text
src/patchloop/memory/
├── models.py          # 记忆类型、来源、查询、召回结果和压缩报告
├── store.py           # SQLite 持久化、索引、幂等写入和 schema 迁移
├── working.py         # 短期工作记忆状态机
├── semantic.py        # 语义事实抽取、去重、冲突与替代
├── episodic.py        # 情景切分、结果归因和失败经验
├── retrieval.py       # 混合召回、排序、多样性和预算分配
├── compression.py     # 去重、分层聚合、关键事实保护和递归压缩
└── manager.py         # Runtime 与 Context Engine 的统一入口
```

`ContextEngine` 继续负责最终消息预算与原子 assistant/tool 消息组；`MemoryManager` 负责记忆写入、检索和压缩。两者不得互相复制职责。

## 5. 开发任务

### LCM-00：建立长上下文基线和评测协议（已完成）

先实现固定评测框架，不修改现有记忆策略。

开发内容：

- 新增可生成 20、50、80、120 步历史的确定性长任务驱动器。
- 为每条关键事实标记产生步骤、有效时间、预期召回步骤和相关查询。
- 支持 `recent-only`、当前 `TaskMemory V1` 和后续 `hierarchical-memory` 三种变体。
- 报告成功率、关键事实存活率、过期事实召回率、重复失败率、输入 Token、费用、时延和压缩次数。
- 真实 DeepSeek 评测固定任务、配置和提示，每个最终配置至少重复 3 次。

完成标准：在任何新记忆代码合入前生成当前系统基线，并能一条命令重复运行。

LCM-00 已于 2026-08-30 完成，协议、确定性三轮基线和 DeepSeek V4 Flash 三轮基线见 [LCM-00 验收记录](milestones/LCM_00_ACCEPTANCE.md)。

### LCM-02：实现持久化 Memory Store（已完成）

开发内容：

- 在 SQLite 增加 `memory_records`、`memory_sources` 和 `memory_compactions` 表及必要索引。
- 使用任务 ID、类型、状态、步骤范围和内容哈希查询。

- 预留语义向量接口，但首版不得强制外部向量数据库或网络服务。

完成标准：重复恢复不会产生重复记忆；迁移失败不破坏现有任务数据。

LCM-02 已于 2026-08-30 完成，共享 SQLite schema、恢复幂等性、事务回滚和查询边界见 [LCM-02 验收记录](milestones/LCM_02_ACCEPTANCE.md)，持久化决策见 [ADR-011](adr/ADR-011-transactional-sqlite-memory-store.md)。

### LCM-03：实现短期工作记忆（已完成）

开发内容：

- 从任务目标、活动计划、最近工具结果和工作区变更增量维护工作状态。
- 对用户约束、禁止文件、活动错误和未解决问题提供 pin 机制。
- 阶段完成后将稳定事实提升到语义记忆，将完整过程写入情景记忆。
- 对已解决问题和旧错误执行明确淘汰，不保留重复工具输出。
- 为工作记忆设置独立 Token 预算和确定性裁剪顺序。

完成标准：100 步任务中工作记忆大小保持有界，活动约束和当前错误保持 100% 可见。

LCM-03 已于 2026-08-30 完成。Runtime 现在维护版本化工作记忆快照，将其作为强制系统上下文注入并随 checkpoint 恢复；100 步端到端任务验证了预算上界、约束和活动错误可见性。阶段完成和成功验证会通过 LCM-02 的事务边界提升为带来源的长期记录。详见 [LCM-03 验收记录](milestones/LCM_03_ACCEPTANCE.md) 和 [ADR-012](adr/ADR-012-bounded-runtime-working-memory.md)。

### LCM-04：实现情景记忆（已完成）

开发内容：

- 从 `step.started`、工具调用、写入、测试、失败、重新规划和检查点事件切分情景。
- 为每个情景生成意图、动作、观察、结果、路径和错误分类。
- 建立失败情景与恢复情景之间的因果链接。
- 支持按文件、错误类型、计划阶段和时间范围查询。
- 恢复任务时能够定位最后一个已验证情景，不重复已完成写入。

完成标准：固定失败恢复任务能够召回原失败原因，并且 Agent 不再执行完全相同的无效方案。

LCM-04 已于 2026-08-30 完成。Runtime 现在按工具调用和 checkpoint 边界生成带来源的结构化情景，维护失败到恢复的因果链接，并在恢复时从快照或持久化记录定位最后一个已验证情景。稳定的完全相同失败调用会在执行前阻止；策略前置条件和测试失败仍允许在状态变化后重试。详见 [LCM-04 验收记录](milestones/LCM_04_ACCEPTANCE.md) 和 [ADR-013](adr/ADR-013-event-segmented-episodic-memory.md)。

### LCM-05：实现语义记忆（已完成）

开发内容：

- 首版使用确定性抽取器从任务约束、计划证据、文件读取、diff 和测试结果生成类型化事实。
- 对内容归一化并按作用域、类型和来源去重。
- 实现事实冲突检测、替代链和来源可靠性优先级。
- 区分“观察到”“推断出”“用户明确要求”和“测试已验证”，禁止把推断自动提升为已验证事实。
- 将模型辅助抽取定义为可插拔接口，不作为核心测试或离线运行的必需依赖。

完成标准：后续权威事实能替代早期过期事实，召回结果不同时返回冲突的活动版本。

LCM-05 已于 2026-08-30 完成。Runtime 现在使用确定性抽取器生成类型化事实，以 `verified > user_asserted > observed > inferred` 的固定权威解析冲突，保存双向替代链并默认只查询唯一活动版本；模型辅助输出被强制限制为推断。详见 [LCM-05 验收记录](milestones/LCM_05_ACCEPTANCE.md) 和 [ADR-014](adr/ADR-014-authority-aware-semantic-facts.md)。

### LCM-06：实现跨层检索和预算分配（已完成）

开发内容：

- 查询由任务目标、活动计划、当前错误、目标文件和最近动作共同构成。
- 工作记忆直接进入候选集；语义和情景记忆按词项、符号、路径、时间、重要度、置信度和来源可靠性混合排序。
- 使用多样性约束避免前 K 条都是同一测试日志或同一文件的重复事实。
- 排除 `superseded`、`invalidated` 和与当前任务作用域不匹配的记录。
- 在总上下文预算内分别为工作记忆、语义记忆、情景记忆和原始最近步骤分配额度，并输出选择原因。

完成标准：标注集上的 `memory_recall@5` 不低于 0.90，`memory_precision@5` 不低于 0.70，过期事实召回率为 0。

LCM-06 已于 2026-08-30 完成。Runtime 现在以目标、计划、错误、路径和最近动作构建查询，使用词项/符号/路径/时间/重要度/置信度/来源质量混合排序，并执行跨层多样性和工作 20%、语义 12%、情景 8%、最近历史 60% 的可收缩预算。固定任务达到 Recall@5 1.00、Precision@5 0.80、过期事实召回率 0。详见 [LCM-06 验收记录](milestones/LCM_06_ACCEPTANCE.md) 和 [ADR-015](adr/ADR-015-budgeted-cross-layer-memory-retrieval.md)。

### LCM-07：实现安全的分层记忆压缩（已完成）

压缩分四级执行：

1. 无损归一化：去除重复观察、重复 diff、相同错误和重复测试输出。
2. 记录级压缩：把同一事实的多次证据合并，保留来源列表和最新状态。
3. 情景级压缩：把连续探索或失败恢复步骤聚合为一个情景。
4. 代际压缩：旧情景进一步汇总为阶段摘要，但保留关键事实 ID 和原始 Trace 链接。

压缩不变量：

- 用户约束、禁止事项、未完成计划、失败方案、最终决策和测试证据不得静默删除。
- `superseded` 事实可以不进入上下文，但替代关系必须可查询。
- 相同输入重复压缩应得到相同内容哈希，不得不断改写摘要。
- 原始事件不删除；任何压缩记录都能追溯到来源步骤。
- 压缩输入和输出都经过凭据脱敏并继续标记为不可信数据。

完成标准：冗余历史压缩比达到 6:1 以上时，关键事实存活率仍为 100%，重复压缩结果幂等。

LCM-07 已于 2026-08-30 完成。确定性四级压缩会保护关键记录，仅失效派生原记录并保留完整来源与跨代谱系；固定任务达到约 12.40:1 压缩、关键记录存活率 100%，重放结果幂等。详见 [LCM-07 验收记录](milestones/LCM_07_ACCEPTANCE.md) 和 [ADR-016](adr/ADR-016-safe-generational-memory-compression.md)。

### LCM-08：集成 Runtime、Context Engine 与恢复流程

开发内容：

- 每个工具结果和步骤结束后由 `MemoryManager` 增量摄取事件。
- 每次 Provider 调用前检索 `MemoryBundle`，再交给 `ContextEngine` 做最终硬预算裁剪。
- 检查点记录记忆水位和待处理事件位置，恢复时只处理缺失部分。
- 记忆写入或压缩失败不得损坏工作区；根据错误类型降级到当前 `TaskMemory V1`。
- 保持 assistant/tool 原子消息组和现有 Token、费用、时间预算不变量。

完成标准：中断恢复前后的记忆集合和最终召回结果一致，不重复工具副作用。

### LCM-09：补齐可观测性、安全与 CLI

开发内容：

- 新增 `memory.written`、`memory.retrieved`、`memory.superseded`、`memory.compacted` 和 `memory.fallback` 事件。
- 在报告中记录各类记忆数量、召回命中、压缩比、陈旧命中、读写耗时和上下文占用。
- 新增 `patchloop memory <task-id>`，支持按类型、查询、步骤和状态查看，并展示“为何召回”。
- `replay` 能定位一次错误决策使用了哪些记忆。
- 增加仓库 Prompt Injection 和凭据写入记忆的安全测试。

完成标准：任一召回结果都能解释分数、来源和状态；敏感原文不会进入 SQLite、Trace 或 Provider 上下文。

### LCM-10：运行消融实验并只优化真实失败

必须比较：

- 仅保留最近步骤。
- 当前 `TaskMemory V1`。
- 分层记忆但关闭语义记忆。
- 分层记忆但关闭情景记忆。
- 分层记忆但关闭压缩。
- 完整 Memory 2.0。

完成标准：先分类失败，再优化排名最高的两类问题；不得根据单个成功样例全面重构。

## 6. 长上下文开发任务集

至少建立以下 8 个锁定任务，每项均包含公开测试和 Agent 运行时不可见的隐藏验收：

| 任务 | 历史压力 | 核心判定 |
| --- | --- | --- |
| early-constraint-survival | 早期给出禁止修改文件，随后插入大量噪声步骤 | 最终补丁不触碰禁止文件 |
| superseded-api-contract | 早期接口要求被后续权威要求替代 | 只使用最新有效接口，旧事实保留替代关系但不召回 |
| failed-strategy-avoidance | 一个方案早期失败，长时间后出现相似错误 | 不重复相同失败动作，能引用原失败原因 |
| checkpoint-memory-resume | 写入、测试后强制中断并恢复 | 不重复写入，恢复前后记忆一致 |
| delayed-cross-file-evidence | 关键线索分布在相距很远的多个文件读取情景 | 能组合至少 3 段证据完成跨文件修改 |
| repetitive-test-output | 产生大量相同测试日志和 diff | 高压缩比下保留首次原因和最终验证 |
| memory-poisoning-defense | 仓库内容包含伪系统指令和假凭据 | 指令不升级权限，凭据不进入持久记忆 |
| multi-generation-compression | 历史经历至少 3 代压缩 | 关键约束、失败方案和来源链全部可恢复 |

任务生成器必须固定噪声内容和关键事实位置，不能让评测器通过读取 Agent 生成的摘要决定答案。隐藏测试只判断最终行为、变更范围和记忆审计不变量。

## 7. 指标与退出标准

### 确定性质量门禁

- 120 步模拟中上下文硬预算违反次数为 0。
- pinned 约束、未完成事项和最终测试证据存活率为 100%。
- 已替代事实进入活动召回结果的比例为 0。
- 相同失败动作的重复执行次数为 0。
- 检查点恢复后的记忆内容哈希与未中断运行一致。
- 记忆持久化、Trace 和 Provider 上下文中的秘密泄漏次数为 0。
- 在 10,000 条本地记录上，摄取与检索组合的 p95 目标低于 50 毫秒；若未达到，报告实际数据后再优化。

### 真实模型退出标准

- 8 个长上下文任务，每个最终配置使用 DeepSeek V4 Flash 重复至少 3 次。
- 完整 Memory 2.0 的独立成功率不得低于当前 `TaskMemory V1`。
- 若成功率持平，平均输入 Token 至少降低 20%；若 Token 持平，平均步骤至少降低 15%。
- 工具失败率、越界变更率和恢复重复副作用不得高于基线。
- 报告均值、最小值、最大值和逐任务结果，不选择性报告最佳一次。

## 8. 实施顺序

| 阶段 | 任务 | 依赖 | 可并行项 |
| --- | --- | --- | --- |
| A：基线与契约 | LCM-00、LCM-01 | 无 | 评测 fixture 与领域模型可并行 |
| B：存储与短期状态 | LCM-02、LCM-03 | LCM-01 | SQLite 与工作记忆可并行 |
| C：长期记忆 | LCM-04、LCM-05 | LCM-02 | 情景记忆与语义记忆可并行 |
| D：召回与压缩 | LCM-06、LCM-07 | LCM-03～05 | 先固定接口，再分别实现 |
| E：运行时集成 | LCM-08、LCM-09 | LCM-06～07 | CLI 与事件测试可并行 |
| F：验收优化 | LCM-10 | 全部 | 消融变体可以并发运行 |

第一批实现应从 LCM-00 和 LCM-01 开始，不应先改 `ContextEngine` 的裁剪阈值。

## 9. 非目标

- 首版不实现跨用户的全局人格记忆。
- 首版不在不同仓库之间自动共享事实。
- 首版不依赖云端向量数据库或额外摘要模型。
- 不删除原始 Trace 来换取存储空间。
- 不把模型生成的摘要视为无来源的事实。
- 不以更低 Token 单一指标替代代码任务正确率。

## 10. 主要风险

| 风险 | 控制措施 |
| --- | --- |
| 摘要错误逐代放大 | 保留不可变来源、内容哈希、压缩代数和关键事实 pin |
| 过期事实污染决策 | 显式状态与替代链，默认排除非活动事实 |
| 记忆召回形成上下文注入 | 所有记忆保持不可信数据边界并统一脱敏 |
| 频繁写入拖慢 Runtime | 增量批处理、SQLite 索引和 p95 性能门禁 |
| 语义召回不可复现 | 核心测试使用确定性抽取和排序，Embedding 只作为可选变体 |
| 压缩过早导致性能退化 | LCM-00 基线先行，所有压缩策略必须通过端到端 A/B |
