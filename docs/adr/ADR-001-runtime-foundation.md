# ADR-001：首版运行时采用轻量同步状态机

## 状态

已接受。

## 背景

PatchLoop 的首要目标是验证“模型决策、受控工具、观察反馈、结构化轨迹”闭环，而不是提前引入分布式任务系统或重量级 Agent 框架。首版只支持 Python 仓库和 CLI，且单个任务顺序执行。

## 决策

- 使用 Python 3.12 及以上版本、Pydantic 和 Typer。
- Provider 通过自有协议接入，核心运行时不依赖特定模型厂商。
- 工具必须注册到 Tool Gateway，并使用 Pydantic 校验参数。
- 所有路径先规范化，再验证其位于任务仓库内。
- 运行时采用同步、单 Agent、有限步数状态机。
- 事件先写入追加式 JSONL；任务元数据在 SQLite 里程碑前使用原子替换的 JSON 文件。
- 单元测试和集成测试使用确定性的 Fake Provider，不调用真实模型。

## 后果

这一方案便于测试状态迁移、工具安全边界和失败分类，也能生成完整的离线执行轨迹。同步状态机会限制并行工具调用吞吐量，JSON 文件也不适合并发写入；这些问题将在持久化和调度里程碑中分别解决。
