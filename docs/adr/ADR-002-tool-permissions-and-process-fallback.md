# ADR-002：工具权限分级与本地测试进程降级

## 状态

已接受。

## 背景

PatchLoop 开始支持修改文件和运行测试后，只依赖仓库路径边界已经不足以控制风险。写工具可能覆盖错误文件，通用 Shell 又能轻易绕过系统的工具协议。Docker 沙箱属于后续里程碑，但当前版本仍需要一个可测试的本地执行闭环。

## 决策

- 工具分为 `read`、`write`、`execute` 三个权限等级。
- Tool Gateway 默认只开放 `read`，写入和执行必须通过策略显式启用。
- 首版写操作只提供“新建文件”和“带出现次数断言的精确替换”，不提供删除、任意覆盖或通用 Shell。
- 文件写入使用同目录临时文件和原子替换，并在首次修改前记录原始内容。
- 变更跟踪器根据原始内容生成统一 diff。
- 本地执行降级只接受 pytest 和 unittest，限制工作目录、环境变量、时间和输出长度，并拒绝仓库外测试路径。
- 仓库文件枚举不跟随符号链接，防止只读搜索泄露仓库外内容。

## 后果

当前工具可以完成小范围缺陷修复并提供可审查 diff，同时默认策略保持最小权限。精确替换不适合复杂重构，本地子进程也无法提供容器级网络和系统调用隔离；因此执行来自不可信仓库的测试仍需用户信任，Docker 沙箱接入前不会把该降级模式描述为强隔离。
