# ADR-004：使用 SQLite 步骤检查点恢复任务

## 状态

已接受。

## 背景

第三周运行时只在内存中维护模型消息、计划、工具历史和预算。进程退出后无法继续任务，JSON 任务文件也不能关联查询步骤、工具调用和产物。第四周需要建立本地优先的持久化边界，并保证恢复任务不会再次执行已经确认完成的写操作。

## 决策

- 使用 Python 标准库 `sqlite3` 建立单文件状态库，当前不引入 ORM；数据迁移需求出现后再评估 SQLAlchemy。
- SQLite 开启 WAL 和外键约束，分别保存任务、Agent 步骤、工具调用与结果、最新检查点和产物索引。
- 每个工具调用使用任务 ID 与 Provider 调用 ID 的组合作为唯一键，避免跨任务碰撞。恢复期间遇到本任务已持久化的调用 ID 时直接回放结果，不再次调用工具。
- Runtime 在任务开始及每个完整 Agent 步骤结束后保存检查点。检查点包含模型消息、计划、重规划状态、变更快照、工具历史、循环检测状态和累计预算。
- 任务保持 `running` 状态时允许恢复；完成、失败或取消的任务不可恢复。
- 写入和执行权限随任务持久化，恢复时沿用原权限集合，不通过恢复动作扩大权限。
- JSONL 继续承担面向调试的顺序事件轨迹，SQLite 承担可查询状态和恢复数据，两者职责分离。

## 后果

强制中断后，CLI 可以从最后一个完整步骤恢复模型上下文、变更视图和预算，并跳过具有相同调用 ID 的已确认工具结果。当前检查点粒度是 Agent 步骤边界；若进程恰好在外部写入完成、但工具结果尚未写入 SQLite 的极窄窗口退出，系统无法证明该操作是否完成。后续需要工作区事务日志或工具级预写记录才能覆盖这一窗口。
