# ADR-005：使用 Python AST 和可插拔稀疏语义通道构建混合检索

## 状态

已接受。

## 背景

前四周的 Agent 只能依靠文件枚举和逐行文本搜索定位代码。自然语言任务使用同义词、实现意图或测试意图时，精确文本匹配容易漏掉目标；同时，模型无法知道一个候选是由符号、引用还是测试关联召回的。

## 决策

- 首版 Repository Intelligence 与项目边界一致，只索引 Python 文件，并使用标准库 `ast` 提取模块、类、函数、方法和加载引用。
- 索引快照只保存结构化元数据、摘要和内容哈希，不复制源码正文；加载时通过文件集合和 SHA-256 判断是否过期。
- 引用解析优先匹配同文件符号，再退化为仓库内同名符号。测试映射基于测试文件命名、导入模块、导入符号和引用证据建立。
- 混合排序融合关键词、符号名、稀疏语义、路径、符号图距离、Python 文件类型、最近访问和源码—测试关联八类特征。
- 定义 `SemanticEncoder` 协议。默认 `SparseSemanticEncoder` 使用无需联网的领域同义词归一化和稀疏余弦相似度，后续可以替换为 Embedding Provider。
- 检索按文件去重，并返回精确行号、符号、代码片段、各特征分数、来源标识和主要排序理由。
- 使用固定 JSON 任务集同时运行纯文本基线和混合检索，保存逐任务结果和 Recall@K。

## 后果

Agent 获得了可解释、确定性且无需外部模型的代码定位能力，中文常见开发意图也可通过受控词表映射到检索特征。当前引用解析不处理动态导入、运行时派发、复杂别名和跨语言调用；稀疏语义通道也不是通用神经语义模型。后续可以在保持 `SemanticEncoder` 和结果证据协议不变的情况下替换实现，并用更大留出集验证提升。
