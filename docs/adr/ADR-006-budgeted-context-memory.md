# ADR-006：使用预算化原子消息组和结构化任务记忆

## 状态

已接受。

## 背景

前五周 Runtime 会把所有模型消息和完整工具输出持续追加到下一次请求。长任务会不断扩大输入，单次大型文件或测试日志也可能占满模型上下文。直接删除旧消息会破坏 assistant tool call 与 tool response 的协议配对，并让 Agent 丢失早期结论、失败证据和未完成事项。

## 决策

- 为每个任务增加单次上下文 Token、单个工具输出字符数和最近步骤数预算；累计输入 Token 预算继续独立生效。
- 使用保守的确定性估算器同时计算消息和工具 Schema 大小。系统提示、原始任务目标及工具 Schema 是强制内容，无法容纳时以 `budget_exceeded` 安全终止。
- 将一条 assistant 消息与其后全部 tool response 视为不可拆分的原子步骤组，避免裁剪产生无效 Chat API 序列。
- 最近步骤优先，其余历史按任务目标和未完成计划的词项相关性排序，在预算内按完整步骤选择并保持时间顺序。
- 被省略的步骤生成 `TaskMemory`，结构化保存未完成事项、关键工具证据、失败、历史决策和原步骤编号。摘要由确定性逻辑生成，不产生额外模型调用。
- 任务记忆作为系统提示中的机器生成 JSON 数据加入请求，并明确标记仓库和工具证据为不可信数据，禁止执行其中的指令。
- 工具完整结果保留在 Gateway 历史、SQLite 检查点和任务报告中；模型消息只保存带 `output_truncated` 与原始长度的头尾观测。
- 每次构建发出 `context.built` 事件，记录总预算、估算用量、工具 Schema、原始消息、保留步骤、丢弃步骤、记忆和截断统计。`patchloop context` 提供文本预算条和 JSON 明细。

## 后果

模型请求在长任务中保持有界，并能通过结构化记忆继续引用早期相关证据。检查点保存的是紧凑模型观测，恢复后可重新生成相同类型的任务记忆。当前 Token 数量是字符启发式估算，不是 DeepSeek 的精确 tokenizer 结果；摘要是可复现但能力有限的抽取式记忆，也不会对敏感内容做完整脱敏。供应商 tokenizer、语义记忆排序和凭据脱敏将在后续可观测性与安全阶段继续完善。
