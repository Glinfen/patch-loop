# ADR-007：使用失败关闭的 Docker 沙箱和派生式可观测性

## 状态

已接受。

## 背景

前六周已有精确命令白名单、仓库路径边界和 JSONL 事件，但执行工具仍直接运行在宿主机，权限只有读、写、执行三级开关，轨迹也缺少稳定序号、指标汇总和失败回放。工具与模型内容还可能把凭据写入上下文、检查点或日志。

## 决策

- 执行工具通过 `CommandSandbox` 协议运行。CLI 默认使用 Docker 后端；镜像不存在、Docker 不可用或容器启动失败时拒绝执行，不自动降级到宿主机。
- Docker 容器只绑定当前仓库到 `/workspace`，默认 `--network none`，并设置 CPU、内存、PID、只读根文件系统、临时目录、capability 删除、`no-new-privileges` 和外层超时。
- 保留 `local` 后端用于受信任环境兼容测试，但明确不将其视为操作系统级隔离。
- Tool Gateway 先检查权限与计划，再对路径、命令和动作风险进行判断。读、写、执行分别对应低、中、高风险；Shell 语法和网络型可执行文件直接判为严重风险并拒绝。
- 中风险及以上动作要求审批。交互模式逐次询问；非交互模式仅把显式 `--allow-write`、`--allow-execute` 视为预授权范围，严重风险始终不可审批绕过。
- 使用一个确定性脱敏器处理 API Key、Bearer Token、密码、Token 和 Secret，覆盖进入 Provider 的消息、Trace、SQLite 和产物。
- JSONL Event 增加事件 ID、Trace ID 和单调递增序号。指标和回放从追加式 Trace 派生，不建立第二套可漂移的运行事实来源。

## 后果

命令执行默认具备明确的容器边界，未授权网络、仓库外路径和危险命令在运行前被拒绝。每次安全判断及工具结果进入已脱敏轨迹，失败可通过 `metrics` 汇总并由 `replay` 定位到事件序号和 Agent 步骤。使用者需要预先构建沙箱镜像；Docker 仍共享宿主机内核，因此不能替代面向恶意租户的虚拟机或 microVM。
