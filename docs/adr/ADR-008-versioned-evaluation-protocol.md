# ADR-008：使用版本化清单和共享成功判定运行评测

## 状态

已接受。

## 背景

此前只有 4 项检索 Recall@1 数据和单个 calculator 修复 fixture，无法批量比较系统变体，也没有统一的仓库版本、难度、任务类型、并发、重试和结果格式。若基线各自定义成功，比较结果会失去意义。

## 决策

- 使用 Pydantic 模型定义版本化 JSON 清单，将仓库、任务和成功条件分离。
- 以确定性文件树 SHA-256 锁定静态 fixture；指纹不匹配和路径越界均在启动 worker 前失败。
- 执行器只返回候选路径、计划步骤和备注；共享判定器计算期望路径 Recall。
- 使用有界线程池并发执行任务，对失败和异常执行有限重试，最终报告保持清单顺序并保存全部尝试。
- 提供 single-shot、no-plan、text-only 和 PatchLoop 四个离线变体，使用同一清单与成功判定。
- JSON 报告保存总体、难度、任务类型和任务级结果；CLI 一条命令运行单一或全部变体。

## 后果

代码定位能力可以在 CI 中离线复现和横向比较，任务集漂移会显式失败。第八周 PatchLoop 变体包含任务类型路由，因此与无规划及纯文本基线形成可解释差异。当前成功条件只覆盖代码定位，不能代表补丁正确性；未来 Agent 执行器需要扩展候选产物与判定器，以纳入测试、diff、成本和时延。
