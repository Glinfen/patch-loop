# ADR-009：使用组件开关、结果指纹和分阶段优化完成消融

## 状态

已接受。

## 背景

第八周已经建立 30 项固定定位任务和四个基线，但单次结果无法说明波动范围，也没有把失败原因、组件贡献、成本和时延放在同一个实验协议中。直接继续增加检索规则会造成无数据依据的全面优化。

## 决策

- 用不可变 `ExperimentFeatures` 控制规划、检索、混合检索、反思、任务类型路由和 Top-K，不为每个消融复制执行器。
- 在同一套件上运行完整系统、去规划、去检索和去反思；所有变体共享仓库指纹、任务和成功判定。
- 为失败建立固定 taxonomy，并保留每类最多 5 个任务示例。
- 从单次基线失败数量排序选择前两类：测试/源码混淆使用任务类型路由修复，文档未进入 Python AST 索引使用文档二次检索修复。
- 连续运行 5 轮。成功率统计最小值、最大值和总体标准差；任务 ID、通过状态和最终候选路径生成 SHA-256，用于排除时延噪声后判断结果稳定性。
- 报告本地真实时延、确定性 Token 估算和执行成本。离线执行器不调用 Provider，成本必须记录为 0 美元，不能用虚构模型价格填充。

## 后果

实验可以复现组件贡献和优化路径：规划在当前定位切片不改变成功率，检索和文档反思具有可测贡献。类型路由与文档二次检索分别解决两类最大失败，而非重构无关模块。结果指纹能证明功能输出稳定，但本地时延仍受主机负载影响；真实 Agent 成本、生成质量和端到端修复率仍需 Provider 任务集。
