# ADR-010：不可变证据与版本化派生记录构成分层记忆契约

## 状态

已接受。

## 背景

`ContextEngine` 当前会从被裁剪的消息临时抽取 `TaskMemory`。它能在有限预算内保留部分早期证据，但没有稳定的长期记忆实体、来源引用、生命周期、替代关系或压缩谱系。若直接在 SQLite、检索器和 Runtime 中分别定义字典结构，后续迁移将无法区分原始证据与模型生成的派生结论，也无法可靠处理旧事实被新事实替代的情况。

LCM-01 需要先固定领域契约，不提前实现存储、抽取、召回算法或 Context Engine 集成。

## 决策

### 版本和兼容性

- 所有记忆数据模型继承同一个严格 V1 基类，序列化时始终写出 `schema_version: "1.0"`。
- V1 读取器允许缺少版本字段的早期 V1 数据，并补为 `1.0`，作为首次持久化前的迁移桥梁。
- 未知版本、未知枚举值和未知字段全部失败关闭，不能被静默降级为当前语义。
- 模型默认冻结；状态变化通过创建新版本或经过验证的副本表达，持久层不得原地改变原始证据。

### 原始证据与派生记忆

- Trace、工具结果、用户消息和检查点继续作为不可变审计证据，记忆不得成为唯一事实源。
- `MemorySource` 只保存稳定定位信息和证据 SHA-256，不复制完整原始载荷。不同来源类型必须提供对应的事件、工具调用、检查点或父记忆定位符。
- `MemoryRecord` 是可删除、可重建的派生视图。语义记忆和情景记忆至少引用一个来源；短期工作记忆允许在任务初始化时暂时没有来源。
- `content_hash` 由记忆类型、检索文本和结构化内容的规范 JSON 计算。载荷与哈希不一致时拒绝读取，为 LCM-02 的幂等写入提供稳定键。

### 类型、作用域和生命周期

- `MemoryKind` 固定为 `working`、`semantic` 和 `episodic`。工作记忆只能位于任务作用域；语义和情景记忆可按任务或仓库作用域组织。
- 每条记录具有结构化内容、检索文本、来源、重要度、置信度、估算 Token、压缩代数、访问次数和最后召回原因。
- 状态固定为 `active`、`superseded` 和 `invalidated`。`superseded` 表示存在替代记录，必须设置 `superseded_by_id`；`invalidated` 表示事实失效但没有替代者。
- 新记录用 `supersedes_id` 指向旧记录，旧记录用 `superseded_by_id` 指向新记录。完整链验证要求关系双向、同任务、同类型、同作用域、时间单调且无环。

### 查询、召回和压缩

- `MemoryQuery` 固定类型、状态、作用域、路径、步骤、时间、置信度、数量和 Token 预算过滤器，并拒绝冲突范围。
- `MemoryHit` 同时保存最终分数、相关性、时效性、来源质量和可解释召回原因。
- `MemoryBundle` 校验排名连续、任务和过滤器一致、来源完整以及总 Token 不越界。它是未来 `MemoryManager` 交给 `ContextEngine` 的唯一召回边界。
- 压缩操作固定为去重、合并、摘要和裁剪。`CompressionReport` 保存输入、输出、受保护记录、移除记录和压缩代数；受保护记录不得被移除，输出 Token 不得大于输入。
- 压缩生成记录必须声明父记录和大于零的代数；未压缩记录不得伪造压缩谱系。

## 后果

LCM-02 可以直接围绕稳定 ID、内容哈希、来源和状态建立表与索引；后续检索、压缩和 Runtime 集成共享同一组验证规则。错误的替代链、无来源长期记忆和不受支持的未来数据会在进入存储前失败。

代价是模型约束较严格，未来增加类型或字段必须显式升级 schema 并提供迁移。`MemorySource` 只保存证据指针，因此读取完整证据仍依赖 Trace 和检查点存储。LCM-01 不改变当前 `TaskMemory V1` 行为，也不声称已经实现持久化或分层召回。
