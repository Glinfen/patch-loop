# ADR-011：使用共享 SQLite、事务迁移和内容寻址持久化派生记忆

## 状态

已接受。

## 背景

LCM-01 固定了版本化记忆契约，但记忆仍不能跨进程保存、按来源查询或在检查点恢复时去重。PatchLoop 已经使用一个启用外键、WAL 和事务回滚的 SQLite 文件保存任务与检查点。另建数据库会让任务删除、恢复和备份失去原子边界，而直接把全部模型塞进单个 JSON 字段又无法建立任务、类型、状态、步骤和内容哈希索引。

LCM-02 需要提供稳定持久化能力，但不能提前耦合 LCM-03 的工作记忆状态机或强制安装外部向量数据库。

## 决策

### 共享数据库与迁移

- `SQLiteStore` 与 `SQLiteMemoryStore` 共享同一个数据库文件；前者继续负责 Runtime，后者独立拥有记忆迁移、写入和查询逻辑。
- 使用 `patchloop_schema_migrations` 按组件记录版本。Memory schema V1 在 savepoint 内逐条执行 DDL，任何失败都会回滚本次 schema 变化。
- 高于当前实现的 schema 版本失败关闭；已存在但不完整的当前 schema 同样拒绝启动。
- 迁移只新增记忆对象，不重写 `tasks`、检查点或工具历史。旧数据库第一次打开时自动升级。

### 关系索引与版本化载荷

- `memory_sources` 保存来源定位、证据哈希、步骤、路径和完整 V1 JSON。
- `memory_records` 保存任务、类型、状态、作用域、内容哈希、质量、压缩代数和完整 V1 JSON。
- `memory_record_sources` 建立记录与来源的多对多关系，保证查询和来源完整性。
- `memory_compactions` 保存压缩代数、输入输出集合和完整 V1 报告。
- 为任务加类型/状态、内容哈希、作用域、创建时间、来源步骤、来源路径和压缩代数建立组合索引。
- JSON 是领域契约的权威序列化；关系列是可重建的检索投影，不能单独解释为完整记忆。

### 安全、幂等和事务

- 来源、记录、压缩报告和查询在进入数据库或可选检索器前统一经过 `SecretRedactor`。
- 内容哈希在脱敏后重新计算，数据库不得保存原始秘密或由原始秘密直接生成的记忆内容哈希。
- 来源指纹忽略随机 ID 和捕获时间；记录身份由规范来源、脱敏后内容哈希、类型和作用域组成。恢复时即使重新生成 ID，也返回已存在的规范对象。
- `save_batch` 在一个事务中依次规范化来源、记录和压缩报告。任一未知来源、跨任务引用、ID 冲突或外键错误都会回滚整个批次。
- 同一规范记录允许使用相同 ID 更新生命周期；不同 ID 的相同来源和内容不会产生重复记录。

### 查询和向量边界

- 第一版先用 SQLite 过滤任务、类型、状态、作用域、路径、步骤、时间和置信度，再执行本地词项相关性、重要度、置信度、时效性与来源质量排序。
- 数量和 Token 预算在构建 `MemoryBundle` 前强制执行，未纳入的记录以截断清单返回。
- `MemoryVectorIndex` 只定义可选评分协议。默认路径不联网、不需要向量模型或外部数据库；后续实现可以注入本地或受控语义索引。

### 生命周期和删除

- 记录生命周期更新保持同一内容身份，替代链仍由 LCM-01 的双向无环校验器验证。
- 所有记忆表通过任务外键级联删除。`SQLiteStore.delete_task` 是任务、检查点、工具历史、产物索引和派生记忆的统一数据库删除入口。
- 原始 Trace 文件仍是外部不可变证据，不由 Memory Store 删除或改写。

## 后果

重复检查点恢复不会重复插入来源或记忆；查询可以利用稳定索引而不解析整库 JSON；迁移和批量写入失败不会留下半完成记忆。LCM-03 到 LCM-07 可以直接复用相同事务和查询边界。

代价是数据库同时保存关系投影与 JSON，需要所有写入经过 Memory Store 才能保持一致。当前相关性排序只是确定性本地基线，可选向量协议尚无内置 embedding 实现。LCM-02 只持久化调用方提供的派生记忆，不会自动从 Runtime 事件抽取记忆。
