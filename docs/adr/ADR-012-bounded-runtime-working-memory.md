# ADR-012：使用可恢复状态机维护有界 Runtime 工作记忆

## 状态

已接受。

## 背景

第六周的 `TaskMemory V1` 由 Context Engine 在窗口压缩时从历史重新生成，适合保留早期证据，但不能表达必须持续可见的活动约束、当前错误或未解决问题。LCM-02 已提供长期记忆事务存储，却没有定义 Runtime 每一步如何维护短期状态、何时淘汰或何时晋升。

直接追加工具输出会让内存和提示长度随步骤线性增长；仅依赖模型摘要又会引入不可重复的核心控制状态。工作记忆还必须与旧 `TaskMemory V1` 共存，不能在小上下文中耗尽其证据预算。

## 决策

### 确定性状态机

- `WorkingMemoryManager` 是 Runtime 内的任务级状态机，不替换 Context Engine。
- 状态按稳定键 upsert；每种工具只保留最新紧凑结果，事件按调用 ID 去重。
- 目标、约束、禁止项、运行中计划和活动错误是受保护状态。错误只由同一工具后续成功明确清除，开放问题由显式 resolve 操作清除。
- 工具输出、路径和长期记录在进入工作记忆或存储前统一脱敏。

### 完整快照与紧凑注入分离

- checkpoint 保存完整版本化快照，包括来源指针、阶段事件、晋升键和预算指标。
- 模型上下文使用按类型分组的紧凑 JSON，不重复序列化内部键和来源元数据。
- 总上下文很小时，工作记忆只注入约束、禁止项、计划、错误和问题；关键证据继续由 `TaskMemory V1` 注入。完整状态仍保留在 checkpoint。

### 独立预算与失败关闭

- 任务配置声明工作记忆 Token 上限；Runtime 同时把实际额度限制在总上下文的 20%。
- 淘汰顺序固定，使用步骤和稳定键打破平局，保证相同事件序列产生相同结果。
- 受保护状态永不因裁剪丢失。若其自身超预算，任务以预算错误结束。

### 阶段边界晋升

- 首次完成计划项时，把完成事实和当前阶段动作摘要分别构造成语义、情景记录。
- 成功测试或命令构造验证事实。
- 晋升使用确定性 ID 和有界已晋升键，经 LCM-02 的 `save_batch` 原子写入来源与记录。
- 这里只建立 Runtime 与长期存储的边界；LCM-04 和 LCM-05 仍负责完整情景建模和类型化语义抽取。

## 后果

100 步任务的工作记忆不再随历史增长，约束和活动错误保持可见；checkpoint 恢复不会重新执行晋升或丢失当前状态。Trace、任务报告和指标可以直接观测预算、淘汰和晋升。

代价是 Runtime 同时维护工作记忆与旧 `TaskMemory V1` 两种短期表示。极小上下文需要将证据摘要委托给后者；后续 LCM-06 的统一召回器应把两者纳入同一预算分配和选择理由，届时再评估是否合并表示。
