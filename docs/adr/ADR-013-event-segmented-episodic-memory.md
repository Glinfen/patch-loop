# ADR-013：按工具与 checkpoint 边界切分可恢复情景

## 状态

已接受。

## 背景

LCM-03 能维护当前状态，并在计划完成时生成轻量阶段摘要，但无法按错误、阶段和文件查询完整执行过程，也不能表达某个修正动作恢复了哪个失败。仅保存 Trace 不足以支持在线恢复：Trace 是审计流，没有稳定的情景边界、因果链接或查询预算。

情景切分还会影响执行安全。阻止所有相同失败动作会破坏正常恢复，例如测试失败后必须重新运行同一测试，因缺少 replan 被拒绝的补丁在 replan 后也必须重试；完全不阻止又会允许 Agent 在重新规划后重复同一个确定无效的补丁。

## 决策

### 边界与载荷

- 每个工具结果形成一个情景；步骤持久化前形成一个 checkpoint 边界情景。
- `step_index` 和活动计划提供阶段，工具调用提供动作，结果提供观察、结果和错误，调用路径与变更快照提供文件范围。
- 情景保存为现有 `MemoryRecord` 和一个或多个 `MemorySource`，不新增数据库表。内容使用独立 `episode_schema`，同时保留用于快速恢复的严格 `EpisodeReference`。
- 参数只保存脱敏后的规范指纹，不把完整写入内容复制到长期记忆。

### 因果恢复

- 未解决失败保留稳定 episode ID、工具、错误、观察和动作指纹。
- 同类工具以修正动作成功时链接对应失败；成功验证链接剩余失败并更新 `last_verified_episode_id`。
- 恢复链接只追加到恢复情景，不重写原失败记录，保持不可变来源和内容寻址身份。
- 计划更新是过程节点，但不代表故障已恢复。

### 重复动作策略

- 只对不依赖后续工作区变化的稳定调用级失败执行硬阻断：未知工具、非法参数、路径拒绝和执行错误。
- 权限与计划前置条件、测试失败、命令失败和语法失败只进入提示，不硬阻断。
- 同一 call ID 的持久化结果优先重放，不受失败指纹阻断；新 call ID 的完全相同稳定失败才生成 `no_progress` 结果。

### 查询和恢复

- 在 `MemoryQuery` 增加错误、计划阶段和情景结果过滤，继续组合来源路径、步骤和时间过滤。
- checkpoint 保存有界情景快照。没有快照时，从任务的持久化情景按创建时间和 ID 重建状态；非 LCM-04 的旧情景摘要被安全忽略。
- 只有存在活动失败、最近恢复或验证锚点时才注入 `PATCHLOOP_EPISODIC_MEMORY_V1`，控制正常路径开销。

## 后果

失败恢复任务可以查询原始失败原因、观察修正动作的因果链接，并避免重做确定无效方案；验证后恢复拥有稳定锚点，不需要重复已完成写入。所有记录继续复用 LCM-02 的事务、脱敏、幂等与级联删除。

代价是每个工具步骤通常产生工具情景和 checkpoint 情景两条记录，存储量高于 LCM-03 的阶段摘要；LCM-07 将负责跨代去重与压缩。当前因果判定是确定性规则，不推断跨工具的复杂语义恢复；LCM-05 的类型化事实与 LCM-06 的统一召回可进一步提高判断质量。
