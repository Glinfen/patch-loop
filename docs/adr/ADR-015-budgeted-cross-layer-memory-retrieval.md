# ADR-015：预算化跨层记忆检索

## 状态

已接受。

## 背景

LCM-03 至 LCM-05 已分别提供工作记忆、情景记忆和带权威替代链的语义记忆，但 Runtime 仍只把工作状态和少量恢复状态整体追加到系统消息。SQLite 中的长期事实没有在每次模型调用前参与选择，ContextEngine 也没有为各层和原始最近历史划定独立额度。

直接把所有活动记录拼入上下文会产生三个问题：高频测试日志会占满前 K 条，路径或符号相关事实可能被低价值新记录挤出，长期记忆又可能侵占原始最近步骤所需的空间。若仅依赖文本相似度，还无法表达来源质量、事实权威、路径匹配和时间等信号。

## 决策

### 查询信号

每次 Provider 调用前构建一条确定性查询，由以下信息组成：

- 原始任务目标。
- 尚未完成的活动计划。
- 工作记忆中的当前错误。
- 当前变更文件和工作记忆中的目标文件。
- 最近四个工具动作及其有界观察。

查询先经过凭据脱敏。完成计划项不进入查询，避免旧阶段持续干扰当前工作。

### 候选与作用域

- 工作记忆以当前有界快照直接进入候选，不经过相似度门槛。
- 长期候选只接受当前 task 的 `active` 语义或情景记录。
- task 作用域必须匹配 task ID；repository 作用域必须匹配当前仓库 ID。
- `superseded` 与 `invalidated` 在候选生成前排除，因此后续排序无法把过期事实重新提升。
- 无 SQLite Store 时使用进程内活动语义记录和直接情景恢复快照降级运行。

### 混合排序与多样性

长期记录分数组合词项、代码符号、目标路径、相对时间、重要度、置信度和来源质量。每条选择都输出各分量和多样性 key，便于 Trace 解释。

语义和情景层先按各自额度选择，再按总分合并。语义层最多使用长期候选名额的 60%，为情景层保留空间。相同路径或同类来源默认最多保留两条，并使用文本 Jaccard 相似度施加重复惩罚；跨层路径冲突时优先保留类型化语义事实，再保留最高分情景。

### 预算

总上下文额度按策略分成：

- 工作记忆 20%。
- 语义记忆 12%。
- 情景记忆 8%。
- 原始最近历史和 LCM-00 遗留摘要 60%。

Runtime 会先计算系统消息、用户消息和工具 schema 的强制成本；若剩余空间不足 40%，检索额度按 `working:semantic:episodic = 50:30:20` 等比例收缩，并把未分配空间归入最近历史。ContextEngine 对最近历史额度和总上下文额度分别执行硬上限。渲染 JSON 的元数据开销也计入检索预算，超限时先移除低分长期记录。

### Runtime 与可观测性

检索结果以 `PATCHLOOP_LAYERED_MEMORY_V1` 注入系统消息，保留现有工作/情景前缀兼容行为，并以 `PATCHLOOP_RETRIEVED_LONG_TERM_V1` 标记长期记录。`memory.retrieved` Trace 保存查询、预算、ID、分数、原因和省略项，不复制长期正文。报告、checkpoint 和 TaskMetrics 保存检索次数、长期命中数和累计 Token。

## 后果

Runtime 现在能在每轮决策前使用三层记忆，并且活动事实、作用域、多样性与预算约束在 Provider 之前完成。固定标注任务达到 Recall@5 1.00、Precision@5 0.80、过期事实召回率 0；900-token 旧长任务保持早期证据且峰值从 862 降至 819。

代价是首版排序仍是确定性词项/符号混合，没有向量召回和学习排序；当前会线性扫描该任务全部活动长期记录，以保证一百步之前的关键事实仍能参与召回。LCM-07 将通过安全压缩降低候选规模，LCM-08 再加入统一水位、增量摄取和故障降级。
