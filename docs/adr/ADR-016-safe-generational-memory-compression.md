# ADR-016：安全的代际记忆压缩

## 状态

已接受。

## 背景

LCM-06 会扫描任务的全部活动长期记录。重复测试输出、同一事实的多次证据和连续探索步骤会持续扩大候选集，但直接删除低价值记录会破坏失败追踪、替代链和审计能力；让模型自由生成摘要又会引入非确定性、凭据泄漏和逐代失真。

## 决策

### 四级确定性压缩

`MemoryCompressor` 按固定顺序执行：

1. 对类型、作用域和归一化检索文本相同的记录去重。
2. 对相同语义槽和值的多份证据执行记录级合并。
3. 按计划阶段、路径和工具聚合连续情景，单组最多 24 条。
4. 仅在调用方显式要求时，把相同类型和作用域的活动压缩记录按每组最多 4 条生成下一代摘要。

只有摘要估算 Token 严格少于输入时才接受压缩。首代默认只处理第 0 代活动记录，因此在更新后的 Store 上重放不会递归重写同一摘要；代际汇总由调用方显式推进。

### 关键记录保护

首代压缩前固定保护用户断言、约束、禁止事项、未完成计划、失败情景、最终决策、类型化验证事实，以及每个工具和路径组合的最新验证与最新恢复情景。保护记录继续保持 `active`，并列入 `CompressionReport.protected_record_ids`。

保护判断不依赖模型。压缩记录继续标记 `untrusted`，摘要正文在计算内容哈希与持久化之前脱敏。

### 生命周期与谱系

被归并的 `MemoryRecord` 只切换为 `invalidated`，其内容、内容哈希和来源不变；原始事件与来源从不删除。新摘要保存：

- 直接输入记录 ID。
- 递归展开的全部历史谱系 ID。
- 所有来源 ID 与来源步骤。
- 压缩级别、代数和确定性 provenance hash。

SQLite 使用一次 `save_batch` 原子写入生命周期变化、新摘要和压缩报告。非活动 `superseded` 记录完全不参与压缩，其双向替代链保持可查询。

## 后果

固定冗余任务把 9,240 Token 压缩到 745 Token，压缩比为 0.0806，即约 12.40:1；六条受保护记录全部存活。相同原始输入生成完全相同的记录、报告和内容哈希，在已更新 Store 上重放不产生新压缩报告。三代压缩后的摘要仍包含全部 48 条原始记录 ID。

代价是首版语义归并依赖类型化槽和值，无法可靠识别任意自然语言同义事实；情景边界也使用固定阶段、路径和工具键。LCM-08 将决定 Runtime 的触发水位、恢复游标和失败降级，不在本 ADR 中自动调度压缩。
