# ADR-018 可解释记忆观测与不可信内容防线

- 状态：已接受
- 日期：2026-09-03

## 背景

LCM-08 已让分层记忆进入 Runtime 主路径，但现有 Trace 只保存总分和文本理由，无法稳定回答某个模型步骤使用了哪些来源、记录当时处于什么状态，也缺少读写与压缩耗时。Memory Store 虽然在写前脱敏，仓库文本中的提示注入片段仍可能作为记忆证据再次进入 Provider。

## 决策

### 查询与逐条解释

新增 `patchloop memory <task-id>`，以现有 `MemoryQuery` 和 SQLite 索引为唯一查询实现。命令支持逗号分隔的记忆类型、状态、文本查询、精确步骤和结果上限。未给文本时使用任务目标。每条结果返回完整的已脱敏记录、总分、相关性、新近度、重要性、置信度、来源质量、匹配词、来源定位和可读召回理由。

Runtime 的 `RetrievalSelection` 同时保存记录状态、来源 ID 和结构化评分分量。`memory.retrieved` 事件不写召回正文，只写这些解释元数据、选择与省略 ID、陈旧命中、读取耗时和上下文占用。

### 指标与回放

MemoryManager 使用单调时钟累计恢复/召回读取、事务写入和压缩耗时，并在快照中保存各类型、各状态库存。TaskReport 记录累计值；Trace 事件记录单次值。`TaskMetrics` 从追加式 Trace 派生写入、替代、召回、压缩、降级、replay、安全过滤、压缩比和最大上下文占用。

`TaskReplay.memory_decisions` 按事件序号和模型步骤列出查询、记录 ID、完整选择解释及省略 ID。重复摄取事件则记录 `event_already_processed` 和 `writes_suppressed`，使恢复后的无写入决策也可审计。

### 不可信内容处理

凭据继续由统一 `SecretRedactor` 在记忆生成、SQLite、Trace 和 Provider 上下文边界处理。新增确定性 `UntrustedContentGuard`，在记忆渲染前识别覆盖上级指令、角色重定义和索取系统提示或凭据等模式，只把命中的片段替换为固定占位符。

过滤结果只记录类别、选择 ID 和记录 ID，不记录命中的原文。工作记忆中的错误与近期动作查询信号，以及 Provider 窗口中的工具历史，使用同一防线，避免通过 `query_signals` 元数据或最近历史旁路。`memory.security_filtered` 使记忆安全处理可计数和回放。

## 后果

任一持久化查询结果和 Runtime 召回记录都能解释分数、来源及生命周期状态，模型错误可以映射回当步使用的记忆。新增字段均提供默认值，旧 Task、checkpoint 和 Trace 仍可读取。

确定性提示注入模式具有保守边界，可能遮蔽仓库中用于测试或文档说明的相同短语；原始工具结果仍保留在经凭据脱敏的审计存储中，而 Provider 接收的记忆副本和工具历史已经过滤。LCM-10 将通过消融实验判断这些附加元数据与过滤是否影响真实任务成功率。
