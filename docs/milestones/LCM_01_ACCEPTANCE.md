# LCM-01 版本化分层记忆领域模型验收

## 结论

PatchLoop 已于 2026-08-30 完成 LCM-01。项目新增独立的 `patchloop.memory` 领域层，固定分层记忆、来源、查询、召回结果、替代关系和压缩报告的 V1 契约。本任务没有修改 `ContextEngine`、SQLite schema 或 Runtime 行为。

## 交付模型

| 契约 | 固定边界 |
| --- | --- |
| `MemoryKind` | `working`、`semantic`、`episodic` |
| `MemorySource` | 事件、工具结果、用户消息、检查点或父记忆的不可变证据指针 |
| `MemoryRecord` | 内容、检索文本、作用域、来源、质量、状态、哈希、压缩和访问元数据 |
| `MemoryQuery` | 类型、状态、作用域、路径、步骤、时间、置信度、数量和 Token 预算 |
| `MemoryHit` | 记录、排名、分数组成和可解释原因 |
| `MemoryBundle` | 查询、命中、完整来源、截断信息和硬预算校验 |
| `CompressionReport` | 压缩操作、输入输出、保护集合、移除集合和 Token 变化 |

所有数据模型使用严格、冻结的 Pydantic V1 契约，序列化时包含 `schema_version`。缺少版本的早期 V1 数据会补为 `1.0`；未知版本、类型和字段会被拒绝。

## 核心不变量

- 长期语义记忆和情景记忆没有来源时拒绝创建；工作记忆只允许任务作用域。
- 内容哈希由类型、检索文本和结构化内容确定，载荷被修改但哈希未更新时拒绝读取。
- `superseded` 记录必须指向替代者，完整替代链必须双向、同边界、时间单调且无环。
- 压缩记录必须声明父记录和压缩代数；保护记录不能同时位于移除集合。
- 召回结果必须符合查询的任务、类型、状态、置信度、数量和 Token 预算，并携带所有来源。
- 原始 Trace 与工具结果是审计证据；记忆只是可重建派生视图。

## 验证覆盖

新增测试覆盖：

- 所有契约 JSON round-trip 和显式 V1 版本。
- 无版本 V1 兼容、未知版本、未知类型及未知字段拒绝。
- 无来源长期记忆、非法来源定位和非法生命周期。
- 内容哈希篡改检测。
- 正常、断裂和成环的替代链。
- 召回来源、排名、过滤条件和 Token 预算。
- 压缩保护集合与非扩张约束。

架构理由见 [ADR-010](../adr/ADR-010-versioned-layered-memory-contracts.md)。
