# LCM-02 持久化 Memory Store 验收

## 结论

PatchLoop 已于 2026-08-30 完成 LCM-02。每个 Runtime SQLite 数据库现在都会事务化迁移 Memory schema V1，并通过 `SQLiteStore.memory` 提供来源、记忆记录、压缩报告、恢复去重和预算化查询。现有 Context Engine 与 Agent 执行策略保持不变。

## Schema

| 表 | 责任 | 关键索引 |
| --- | --- | --- |
| `memory_sources` | 证据定位、哈希、步骤、路径和版本化载荷 | 任务/步骤、任务/路径、来源指纹唯一约束 |
| `memory_records` | 类型、状态、作用域、内容哈希、质量和版本化载荷 | 任务/类型/状态、任务/内容哈希、任务/作用域、创建时间 |
| `memory_record_sources` | 记录与来源多对多关系 | 记录/来源主键、来源反查 |
| `memory_compactions` | 压缩操作、代数、输入输出和版本化报告 | 任务/压缩代数、报告指纹唯一约束 |

`patchloop_schema_migrations` 当前记录 memory version `1`。旧 Runtime 数据库自动新增这些表；未来版本和不完整 schema 均失败关闭。

## 写入与恢复语义

- 所有写入先脱敏，`MemoryRecord.content_hash` 随脱敏后载荷重新计算。
- 来源通过证据与定位指纹去重；记录通过规范来源和内容身份去重。
- `save_batch` 原子写入来源、记录和压缩报告，任何一项失败都会回滚整个批次。
- `restore_checkpoint_state` 复用同一事务。测试使用不同随机 ID 重放相同检查点，最终仍只有 1 个来源和 1 条记录。
- 同一 ID 可以更新记录生命周期；活动查询默认排除已被替代记录。
- 压缩报告只能引用同任务中已经持久化的输入和输出记录。

## 查询能力

`SQLiteMemoryStore.query` 支持以下过滤和约束：

- 任务、记忆类型、状态、作用域和置信度。
- 来源路径与单个来源步骤范围。
- 记录创建时间以及显式包含、排除 ID。
- 最大结果数和硬 Token 预算。

默认排序组合本地词项相关性、重要度、置信度、时效性和来源质量。`MemoryVectorIndex` 允许注入语义分数，但默认实现不访问网络，也不依赖外部向量数据库。内容哈希可通过独立索引接口精确查询。

## 安全和故障测试

新增测试覆盖：

- 仅含旧任务表的数据库无损升级，并验证必要表与索引。
- 高版本拒绝和 DDL 中途失败时保留已有任务，且不留下迁移版本表。
- 来源、记录、压缩报告 round-trip 与索引查询。
- 不同 ID 的检查点重复恢复保持幂等。
- 未知来源导致整个批次回滚。
- 记忆内容和路径写入前脱敏，原始秘密不进入数据库文件。
- 生命周期更新、双向替代链和默认活动记录查询。
- 压缩引用完整性与任务删除级联清理。
- 可选向量评分控制排序且不引入网络依赖。

架构理由见 [ADR-011](../adr/ADR-011-transactional-sqlite-memory-store.md)。
