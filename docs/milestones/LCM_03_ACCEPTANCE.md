# LCM-03 短期工作记忆验收

## 结论

PatchLoop 已于 2026-08-30 完成 LCM-03。Runtime 现在为每个任务维护独立、有界、可恢复的短期工作记忆；用户约束、禁止项、活动计划和当前错误进入强制系统上下文，最近结果与阶段事件按确定性顺序淘汰。完成阶段和成功验证会经 LCM-02 的事务接口提升为带来源的语义或情景记录。

## 状态模型

`WorkingMemorySnapshot` 使用 schema `1.0`，保存以下状态：

- 当前目标，以及从目标中确定性识别的用户约束和禁止项。
- 未完成计划、活动错误、未解决问题和工作区变更路径。
- 与目标直接相关的关键证据、每种工具的最新紧凑结果和当前阶段事件。
- revision、当前与历史最大估算 Token、淘汰数、晋升数和已晋升键。

完整快照进入 Runtime checkpoint。恢复时校验任务 ID 和有效预算，不匹配时失败关闭；旧 checkpoint 没有该字段时从任务目标与当前计划安全初始化。

## 更新、pin 与淘汰

- 工具结果先脱敏再压缩，工作记忆不会重复追加同一种工具的完整输出。
- 目标、约束、禁止项、运行中计划和活动错误受到保护；同一工具成功后会明确删除其旧错误，已解决问题通过显式 API 删除。
- 默认淘汰顺序为最近结果、旧阶段事件、变更路径、开放问题、非活动计划、关键证据；同一优先级按步骤和稳定键决定。
- 如果受保护状态本身超过预算，Runtime 以 `budget_exceeded` 失败，而不是静默丢弃约束或错误。
- 快照保存完整可审计状态；注入模型的是紧凑分类表示。小于 256 Token 的极小工作记忆额度只注入强制状态，并把证据摘要委托给现有 `TaskMemory V1`，避免两个记忆层互相挤占。

## 预算与上下文集成

任务新增 `max_working_memory_tokens`，默认上限为 2,000。Runtime 实际额度取该上限与总上下文 20% 的较小值，且最低为 128，从而保持独立配置同时不破坏小上下文任务。

每次模型调用前，工作记忆以 `PATCHLOOP_WORKING_MEMORY_V1` 强制附加到系统消息；原始消息历史不被改写。Trace 的 `context.built` 保存对应快照，`working_memory.updated` 输出当前用量和累计淘汰，任务报告与指标提供更新、淘汰、晋升和最大用量。

LCM-03 接入后，第六周 900-Token 回归任务仍保留早期证据并完成。工作记忆增加了真实上下文占用，因此基准产物中的最大使用量由 817 更新为 862，仍低于 900 的硬上限。

## 长期记忆晋升

- 计划项首次进入完成状态时，生成一条语义事实和一条当前阶段的轻量情景记录。
- 成功的 `run_tests` 或 `run_command` 生成一条高置信度验证事实。
- 来源 ID、记录 ID 和晋升键均确定生成；重复工具调用和恢复不会重复晋升。
- 来源和记录通过 `SQLiteMemoryStore.save_batch` 同一事务写入，并继续执行写前脱敏和来源完整性检查。

当前情景只覆盖阶段级动作摘要，类型化语义抽取也只覆盖完成项与验证结果。完整事件切分、失败恢复因果关系和权威事实冲突处理仍分别属于 LCM-04、LCM-05。

## 验证证据

新增测试覆盖：

- 目标约束与禁止项识别和 pin。
- 100 次工具执行后工作记忆仍不超过 600 Token，约束和第 50 步活动错误在后续请求中保持可见。
- 重复结果替换、旧事件淘汰、错误成功恢复和问题显式解决。
- 阶段完成只晋升一次语义与情景记录，成功验证晋升语义事实。
- checkpoint round-trip 恢复完全相同的工作上下文。
- 受保护状态超预算时失败关闭。
- Runtime 晋升记录可从 SQLite 按语义与情景类型查询，并保留来源。
- 既有 900-Token `TaskMemory V1` 回归继续通过。

架构理由见 [ADR-012](../adr/ADR-012-bounded-runtime-working-memory.md)。
