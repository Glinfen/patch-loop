# LCM-07 安全分层压缩验收

## 结论

PatchLoop 已于 2026-08-30 完成 LCM-07。新增的确定性压缩器支持无损去重、同事实证据合并、连续情景聚合和显式代际汇总，同时保留关键记录、原始派生记录、来源步骤和完整跨代谱系。

## 四级压缩

- 无损归一化按记忆类型、作用域和归一化检索文本合并重复观察、错误与测试输出。
- 记录级压缩使用语义槽和值归并多份证据，来源取并集，时间与重要度使用输入的最新或最高状态。
- 情景级压缩按阶段、路径和工具组织有界批次，摘要保留首尾观察、步骤范围和结果集合。
- 代际压缩只接受已有压缩记录并显式推进代数，三代测试能够从最终摘要恢复全部原始 ID。

任何级别只有在输出 Token 严格少于输入时才提交。所有 ID、内容、provenance hash 和报告都由规范化输入确定，墙钟时间不参与结果。

## 安全与审计不变量

用户断言、约束、禁止事项、未完成计划、失败方案、最终决策、类型化测试证据、最新验证情景和最新恢复情景不会被归并。固定任务的六条关键记录全部保持活动状态。

被压缩的记录只标记为 `invalidated`，没有物理删除或重写内容。摘要携带直接输入 ID、展开谱系、来源 ID、来源步骤、压缩代数和不可信数据标记；`superseded` 记录不参与压缩，替代链保持原样。摘要写入前再次经过 SecretRedactor，凭据泄漏测试为 0。

SQLite 在同一事务中保存原记录状态、新摘要和 `CompressionReport`。相同输入两次直接压缩结果完全相同；Store 应用首轮结果后再次执行不会产生新记录或报告。

## 固定质量任务

结果保存在 `benchmarks/results/lcm07_compression.json`：

- 77 条输入记录、9,240 输入 Token。
- 71 条冗余记录归并为一条摘要，六条关键记录保持活动。
- 输出 745 Token，压缩比 0.0806，约为 12.40:1，超过 6:1 门槛。
- 关键记录存活率 100%。
- 三代压缩后 48 条原始记录谱系完整。
- 重放幂等，派生摘要秘密泄漏数为 0。
