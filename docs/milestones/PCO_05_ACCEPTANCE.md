# PCO-05 记忆快照与增量发布验收

## 结论

PCO-05 已完成。stable epoch 首次读取层级记忆时发布一次完整 Provider 快照；同一 epoch
后续只发布 added/removed 形式的记忆增量，普通读取在投影未变化时不再重复发送完整记忆。
快照与增量消息作为独立、不可裁剪的动态尾部参与请求组装，不会改写冻结前缀或被历史相关性
重排淘汰。

每个增量使用规范化内容指纹去重，并保存到 checkpoint。恢复后通过快照加增量消息重放出当前
记忆视图；若 epoch 轮换，则清空旧发布流，在新 epoch 重新发布快照。legacy 布局保持原有
完整记忆渲染，不启用增量发布。

## 实现边界

- `MemoryDeltaPublisher` 只接受已经过安全过滤的 Provider 投影，不重新引入记录 ID、来源或
  排序诊断字段。
- 快照与增量均使用固定前缀和规范化 JSON；增量按四类记忆内容计算 added/removed，支持
  确定性重放。
- 增量有独立 Token 上限；超限时拒绝该增量并保留上一个可恢复发布状态。
- `ContextEngine` 支持 pinned tail 消息，确保已发布记忆不会被上下文历史选择器裁剪。
- `context.built` 与 `cache.layout` 记录发布指纹和实际发送的发布消息数量，便于验证完整记忆
  重发次数和缓存前缀变化。
