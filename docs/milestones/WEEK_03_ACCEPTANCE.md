# Week 3 验收记录

## 结论

PatchLoop 已于 2026-08-29 通过第三周“测试反馈与失败恢复”验收。Agent 能区分测试失败与语法错误，在失败后阻止未经重新规划的写入，并在更新计划后完成修正；所有步骤同时受到时间、步骤、Token、费用、工具失败、重规划和无进展预算约束。

## 错误分类

| 类型 | 触发条件 | Runtime 行为 |
| --- | --- | --- |
| `invalid_arguments` | Provider 工具 JSON 无效或参数不符合 Schema | 将结构化错误反馈给模型，不执行工具 |
| `path_denied` | 路径逃逸仓库边界 | 拒绝调用并记录轨迹 |
| `permission_denied` | 权限未开放、缺少计划或失败后未重新规划 | 拒绝写入或执行 |
| `test_failure` | pytest/unittest 非零退出 | 保存测试输出并要求重新规划 |
| `syntax_error` | 测试输出包含语法或缩进错误 | 单独分类并要求重新规划 |
| `command_failure` | 白名单诊断命令非零退出 | 保存退出码和输出并要求重新规划 |
| `timeout` | 工具执行超过限制 | 中止工具并要求重新规划 |
| `provider_error` | Provider 请求或响应协议失败 | 安全终止任务并生成失败报告 |
| `budget_exceeded` | 任一资源或失败预算超限 | 立即终止并说明具体预算 |
| `no_progress` | 重复动作或相同错误达到阈值 | 终止循环并生成诊断报告 |

## 预算

`TaskBudget` 当前覆盖：

- 最大 Agent 步数和墙钟时间。
- 最大输入 Token 和输出 Token。
- 最大估算费用。
- 最大工具失败次数。
- 最大失败后重新规划次数。
- 最大连续相同动作次数。
- 最大相同错误重复次数。

DeepSeek Provider 根据服务端返回的 Token 用量计算估算费用。费率是可配置项，默认值只用于运行时预算，不替代服务商账单。

## 故障注入场景

固定 `calculator_bug` 仓库的恢复测试执行以下流程：

1. 读取缺陷代码并建立初始计划。
2. 故意把除法错误修改为加法。
3. 运行 pytest，得到一次 `test_failure`。
4. 在未重新规划时尝试修复，Tool Gateway 按策略拒绝。
5. 将测试证据写入新计划，重新规划计数增加一次。
6. 应用正确补丁并再次运行 pytest。
7. 第二次测试通过，任务完成。

自动断言确认：

- 最终代码使用真除法。
- 两次验证记录依次为失败和成功。
- 第一次验证错误类型为 `test_failure`。
- 任务报告的重规划次数为 1。
- JSONL 轨迹只包含一次测试失败事件。

## 预算失败验收

自动化测试分别注入以下条件，并确认任务以 `failed` 安全终止且报告仍完整生成：

- 输入 Token 超限。
- 输出 Token 超限。
- 估算费用超限。
- 工具失败次数超限。
- 重规划次数超限。
- 相同工具错误重复两次。
- 相同动作和总步骤超限。
