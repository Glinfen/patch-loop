# Week 4 验收记录

## 结论

PatchLoop 已于 2026-08-29 通过第四周“持久化、检查点与 CLI 完善”验收。任务、步骤、工具结果、检查点和产物已统一写入 SQLite；进程在已确认写入后被强制中断时，新 Runtime 能恢复上下文、计划、变更快照和预算，并继续验证与汇报，不重复该写操作。

## SQLite 状态模型

| 表 | 持久化内容 | 恢复用途 |
| --- | --- | --- |
| `tasks` | 完整任务、状态、预算、执行权限和报告 | 查询状态并判定是否允许恢复 |
| `agent_steps` | 每个步骤的决策、工具结果和状态 | 审计执行过程 |
| `tool_calls` | 调用参数、结果和完成时间 | 按任务 ID 与调用 ID 去重并回放已确认结果 |
| `checkpoints` | 消息、计划、变更快照、循环状态和累计预算 | 从最后一个完整步骤继续 |
| `artifacts` | 报告与轨迹产物路径 | 定位任务输出 |

数据库开启 WAL 和外键约束。JSONL 轨迹继续保留事件时间线，SQLite 负责生命周期查询和恢复状态。

## CLI 生命周期

- `patchloop run`：创建并运行任务，记录预算、权限和非交互配置。
- `patchloop status`：读取持久化任务状态和最终报告。
- `patchloop resume`：仅恢复仍为 `running` 的任务，并沿用原权限。
- `patchloop cancel`：将已创建或运行中的任务标记为取消。
- `patchloop diff`：从最终报告或最近检查点输出统一 diff。
- `patchloop trace`：逐行输出 JSONL 事件轨迹。
- `patchloop task create/show`：通过 SQLite 创建和读取任务。

## 中断恢复场景

端到端测试在固定 `calculator_bug` 仓库执行以下流程：

1. 建立修复与验证计划。
2. 应用除法修复并完成步骤检查点。
3. 在下一次模型调用时注入 `KeyboardInterrupt`，模拟进程强制终止。
4. 从新建 Runtime 和 Tool Gateway 加载 SQLite 检查点。
5. 继续运行回归测试并完成任务。

自动断言确认：

- 中断后的任务仍为 `running`，检查点指向下一个未完成步骤。
- 工作区变更、计划、工具历史和预算被恢复。
- `apply_patch` 的成功事件只有一次，已确认写入没有重复执行。
- 恢复后的测试通过，任务和数据库状态都变为 `completed`。
- CLI 级测试确认 `resume` 可恢复并完成持久化任务。
