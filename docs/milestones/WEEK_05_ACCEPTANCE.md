# Week 5 验收记录

## 结论

PatchLoop 已于 2026-08-29 通过第五周“Repository Intelligence”验收。系统能够为 Python 仓库建立可持久化 AST 索引，提取符号、引用和源码—测试映射，并通过带完整排序解释的 `search_code` 工具与 `search` CLI 执行混合检索。

## 索引能力

- 提取模块、类、函数、异步函数和方法的限定名、签名、文档字符串及精确行范围。
- 记录名称和属性加载引用，并解析到同文件或仓库同名候选符号。
- 根据目录和文件名识别测试，通过导入模块、导入符号和引用建立测试映射。
- 对语法错误文件保留索引问题，不中止整个仓库构建。
- 快照记录 Python 文件 SHA-256；文件增删改后能够识别索引过期。
- 排除 Git、PatchLoop 状态、虚拟环境、缓存和构建目录，并拒绝符号链接逃逸。

## 混合检索与解释

排序融合以下特征：

| 特征 | 作用 |
| --- | --- |
| 关键词重叠 | 保留精确文本基线能力 |
| 符号名匹配 | 提升函数、方法和类名命中 |
| 稀疏语义相似度 | 连接 division/divide/quotient 等领域同义词 |
| 路径匹配 | 利用模块和目录线索 |
| 符号图距离 | 提升直接引用、同文件和测试关联候选 |
| 文件类型 | 当前优先 Python 源码 |
| 最近访问 | 利用本次 Agent 会话已读证据 |
| 测试关联 | 区分实现意图与回归测试意图 |

每个结果均包含仓库相对路径、起止行、限定符号名、代码片段、总分、逐特征分数、召回来源和主要排序理由。默认语义编码器无需联网，并通过协议支持后续替换为真实 Embedding Provider。

## 固定检索评测

固定任务集位于 `benchmarks/retrieval_tasks.json`，包含 4 个代码定位任务，统一使用 Recall@1。执行同一索引和任务集得到：

| 方法 | Recall@1 | 命中数 |
| --- | ---: | ---: |
| 纯文本基线 | 0.25 | 1/4 |
| AST + 文本 + 符号 + 稀疏语义混合检索 | 1.00 | 4/4 |
| 绝对提升 | +0.75 | +3 |

逐任务原始结果保存在 `benchmarks/results/week05_retrieval.json`。该任务集规模很小，数据只证明第五周固定验收集上的行为，不代表对未知仓库的通用成功率。

复现命令：

```bash
patchloop benchmark-search --tasks benchmarks/retrieval_tasks.json --root .
```

## CLI 与 Agent 接入

- `patchloop index`：生成 `.patchloop/repository-index.json` 并报告文件、符号、引用和测试映射数量。
- `patchloop search`：复用有效索引，文件变化后自动重建，输出结构化解释结果。
- `patchloop benchmark-search`：比较纯文本与混合检索，并可写出 JSON 报告。
- `search_code`：作为只读 Tool Gateway 工具提供给 Agent，沿用仓库路径与权限边界。

`search_code` 优先复用有效持久化索引；索引缺失或过期时只在内存重建，不让只读工具产生仓库写入。

## 已知边界

当前引用解析是静态近似，不覆盖动态导入、猴子补丁、运行时派发和复杂重导出；索引只支持 Python。默认稀疏语义词表适合作为确定性离线降级，不替代真实 Embedding 的通用语义能力。
