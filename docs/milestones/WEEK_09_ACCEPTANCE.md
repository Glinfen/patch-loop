# Week 9 验收记录

## 结论

PatchLoop 已于 2026-08-29 通过第九周“实验、优化与稳定性”验收。固定 30 项定位任务连续运行 5 轮，完成规划、检索和反思消融；从基线失败分布选择两类主要问题实施分阶段优化；机器报告同时包含成功率、时延、Token 估算、成本、失败分类和稳定性指纹。

## 基线失败分析

单次文本 Top-1 基线通过 21/30，失败 9 项。固定 taxonomy 的前两类为：

- `documentation_not_retrieved`：6 项。Python AST 索引不包含 Markdown，文档任务没有候选。
- `test_source_confusion`：3 项。目标是测试文件，但 Top-1 返回对应源码。

报告保存了每类失败的任务 ID 示例。没有观察到执行器异常、空候选或不完整 Recall 等其他基线失败。

## 数据驱动优化

只针对上述两类失败增加能力：

| 阶段 | 通过 | 成功率 | 相对基线 |
| --- | ---: | ---: | ---: |
| single-shot baseline | 21/30 | 70% | 0 pp |
| 增加任务类型路由 | 24/30 | 80% | +10 pp |
| 增加文档二次检索 | 30/30 | 100% | +30 pp |

任务类型路由消除 3 项测试/源码混淆；文档二次检索消除剩余 6 项文档失败。没有修改索引、排序器或与证据无关的 Runtime 模块。

## 组件消融

5 轮平均成功率：

| 变体 | 成功率 | 相对完整系统 | 每任务平均时延 |
| --- | ---: | ---: | ---: |
| 完整系统 | 100% | 0 pp | 30.14 ms |
| 去规划 | 100% | 0 pp | 30.55 ms |
| 去检索 | 50% | -50 pp | 9.14 ms |
| 去反思 | 80% | -20 pp | 28.14 ms |

当前成功条件只判断定位，因此规划不改变成功率；这是一项零影响结论，不据此宣称规划对端到端修改无用。去检索虽然更快，但丢失一半任务。去反思稳定丢失全部 6 个文档任务。

## 成本与 Token

实验为确定性离线执行器，不调用 DeepSeek 或其他远程 Provider，所以 5 轮所有变体的费用均为 0 美元。每轮估算输入 Token 均为 421；输出 Token 随候选和计划变化，单次基线 138、完整系统 1040、去规划 457。估算值用于相对比较，不是供应商计费 Token。

## 稳定性

每个变体连续执行 5 轮：

- 所有变体最小成功率等于最大成功率。
- 所有成功率总体标准差为 0。
- 每个变体的 5 个任务结果 SHA-256 完全一致。
- 本地时延保留每轮实测值，不参与结果指纹，因此主机调度噪声不会被误判为功能波动。

完整证据位于 `benchmarks/results/week09_experiments.json`。

## 质量门禁

第九周验收执行 Ruff、mypy、完整 pytest 和分支覆盖率门禁：Ruff 与 mypy 全部通过，pytest 为 73 项通过、1 项因当前 Windows 主机不支持符号链接而跳过，分支覆盖率为 89.22%，高于 85% 门禁。

## 已知边界

实验仍是 Repository Intelligence 定位切片，不是端到端补丁评测；“反思”是确定性第二遍文档检索，不是模型自我批判。时延来自当前 Windows 主机，跨主机不可直接比较。真实 Provider 成本、生成 Token、补丁正确率和多次模型采样波动尚未纳入。
